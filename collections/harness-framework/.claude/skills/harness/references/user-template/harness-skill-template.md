# harness 지시사항
> **🔧 `/harness` 전용 — `/pm`은 이 섹션을 실행하지 않는다.**
> 하네스 빌딩 시 1회 실행. 팀 구조·에이전트·스킬을 설계하고 생성하는 단계.

## 실행 흐름 개요

`/harness` 진입 시 다음 4단계를 순서대로 수행한다. 각 단계의 정식 절차는 아래 참조 안내표에서 지정된 references 파일을 읽어 적용한다.

1. **도메인 분석** — 도메인·재사용 작업 유형·기존 자산 파악 → 한 페이지 요약을 유저에게 제시한다.

> **[체크포인트 1/4 — 도메인 분석 완료]**
> 핵심 작업 유형·재사용 패턴·기존 에이전트/스킬 현황을 한 페이지 요약으로 유저에게 제시한다. 확인을 받은 뒤 패턴 선택으로 넘어간다.

2. **아키텍처 패턴 선택** — 6개 후보 패턴(또는 복합) 중에서 도메인 분석 결과에 부합하는 패턴을 결정한다.

> **[체크포인트 2/4 — 아키텍처 패턴 확정]**
> 선택한 패턴(단일 또는 복합)과 선택 이유를 유저에게 제시한다. 확인을 받은 뒤 역할군 구성·에이전트/스킬 정의로 넘어간다.

3. **역할군 및 스킬 구성** — 필수 역할군과 부속 스킬을 정의한다. 모델 선택·worker 범위 강제 규칙을 적용한다.

> **[체크포인트 3/4 — 팀 구성 확정]**
> 에이전트 목록(역할·모델), 스킬 목록을 유저에게 제시한다. 확인을 받은 뒤 실제 에이전트/스킬 파일 생성으로 넘어간다.

4. **harness 동작 재정의 적용** — SKILL.md 파일명 강제·모델 선택 기준·worker 범위 등 harness 빌딩 시 적용해야 할 운영 정정 사항을 반영한다.

# PM 운영 지침
> **🚀 `/pm` 전용 — 하네스 팀이 구성된 후 PM 에이전트가 매 세션(이슈)마다 따르는 운영 규칙.**
> `/pm`이 이 파일을 받으면 이 섹션만 참조한다. 위의 "harness 지시사항" 섹션은 무시한다.

## 실행 흐름 개요

PM은 매 세션(이슈)마다 다음 흐름을 따른다. 정식 규칙은 아래 참조 안내표에서 지정된 references 파일을 읽어 적용한다.

1. **세션 시작** — resume detection, 플랜 번호 채번, 플랜 디렉토리 생성, dev-plan.md 작성.

> **[체크포인트 4/4 — 플랜 확정]**
> 작성한 `<플랜번호>-dev-plan.md`(작업 단계 구성, 의존성, 담당 에이전트)를 유저에게 제시한다. 확인을 받은 뒤 실제 작업 실행으로 넘어간다.

2. **작업 실행** — 작업 단계와 task 스케줄링, 병렬·순차 분기, 진행 갱신.
3. **세션 종료** — 모든 작업 완료 후 `/clear`, CLAUDE.md·memory·관련 문서 정합성 확인.
