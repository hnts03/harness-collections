## PM 호출 진입 가시성 원칙

PM은 사용자가 `/pm`을 직접 호출한 경우 외에도 외부 스킬(예: `/harness:harness`)에 의해 자동 호출될 수 있다. 자동 호출은 사용자가 PM 사용을 의식적으로 선택한 것이 아니므로, PM이 어떤 다른 행동(Resume Detection·미션 명확화 등)을 시작하기 전에 호출 사실 자체를 명시하고 동의를 받아야 한다. 이 원칙은 공통 운영 원칙(무허가 방향성 결정 금지)의 진입점 적용 사례다.

### 진입 분기 판별 메커니즘 (Hint 전달 방식)

`/pm` 스킬 SKILL.md에 진입점 indicator 라인을 평문으로 박아둔다. SKILL.md 본문은 사용자가 `/pm`을 직접 트리거한 경우에만 PM 컨텍스트로 펼쳐지므로, indicator 라인의 존재 자체가 "직접 호출" 신호가 된다. 외부 스킬이 PM을 호출할 때는 자기 SKILL.md만 펼쳐지므로 자연스럽게 부재가 된다.

- **Indicator 형식 (도메인별 placeholder)**: `<DOMAIN>_PM_ENTRY_POINT: direct (/<skill-name>)`
  - 본 하네스 프레임워크의 경우: `HARNESS_PM_ENTRY_POINT: direct (/pm)`
  - 도메인별 prefix(`<DOMAIN>_`)로 다른 프로젝트 PM과 우발적 매칭을 회피한다.
- **삽입 위치**: `/pm` SKILL.md의 `## 실행` 헤더 직전, 별도 H2 섹션(`## Calling Context`)에 둔다.
- **검사 위치**: PM 에이전트의 STEP 0(Resume Detection) 첫 동작 직전. STEP 0 [0단계]로 신설하여 [1단계] 플랜 번호 확정 이전에 분기를 결정한다.
- **매칭 방식**: 정확 일치(exact match). 부분 매칭은 외부 스킬의 우발적 매칭 위험이 있어 금지한다.
- **Fallback**: indicator 부재 = 비직접 호출(default). 외부 플러그인 호환성을 위한 의도된 동작.

### 비직접 호출 시 PM 절차

다음 순서를 어긴 어떤 동작(STEP 0 [1단계] 플랜 번호 확정, CLAUDE.md 읽기 등)도 indicator 검사 이전에 수행하지 않는다.

1. **자가 announce 메시지 출력** — PM이 호출되어 파이프라인이 시작되려 한다는 사실, 호출 컨텍스트(외부 스킬 추정), 파이프라인 단계 4개를 사용자에게 명시한다.
2. **AskUserQuestion 호출** — `예, PM으로 진행` / `아니오, PM 종료` 2개 옵션 제시. 진입 동의의 핵심 결정만 묻는다(작업 성격 분류 등 부차 절차는 STEP 1 미션 명확화에서 다룬다).
3. **사용자 선택 처리**:
   - `예` → STEP 0 [1단계]로 진행.
   - `아니오` → 종료 메시지 출력 후 즉시 종료. 대안(직접 도구 사용, 다른 스킬 호출, `/pm` 직접 재트리거)을 안내.

### 직접 호출 시 PM 동작

Indicator 발견 시 가시화·동의 절차는 모두 생략하고 STEP 0 [1단계]로 직진한다. 다만 한 줄 안내(`(PM 직접 호출 모드 — \`/<skill-name>\` indicator 확인. Resume Detection으로 진행합니다.)`)를 [1단계] 직전에 출력하여 사용자에게 진입점 확인 신호를 제공한다. 실행 가시성 프로토콜 [규칙 1]과 일관된 톤이다.

### 외부 진입점 호환성

`/harness:harness` 등 외부 플러그인이 PM을 호출할 때 indicator를 출력하지 않으면 자동으로 비직접 호출 분기로 분류된다. 외부 플러그인을 변경하지 않고도 PM 측에서 호출 사실 가시화를 robust하게 처리한다.
